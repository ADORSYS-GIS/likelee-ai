# Plan: Fix Google OAuth Login Flow with Role-Based Routing

## Problem Statement

Currently, when users click "Continue with Google":
- New OAuth users without a complete profile are redirected directly to the dashboard
- The system doesn't properly check if the user's profile matches the selected tab (creator/brand/agency)
- Users don't complete the rest of the signup form after OAuth authentication

## Requirements

Based on user specification:

1. **Check the selected tab** when user clicks "Continue with Google" (creator, brand, or agency)
2. **For existing users with matching profile**:
   - Redirect them directly to their dashboard
3. **For new OAuth users (no profile)**:
   - Redirect to the appropriate signup form for the selected role
   - Email is already verified via OAuth, skip email verification step
   - User must complete remaining profile fields
4. **For users with profile but wrong tab selected**:
   - Show clear error message: "Account not found under this tab. Please try another tab."
   - Log them out to prevent confusion
   - Allow them to switch tabs and try again

## Current Flow Analysis

### Files Involved:
- `likelee-ui/src/pages/Login.tsx` - Login page with tab selection
- `likelee-ui/src/auth/AuthProvider.tsx` - Auth state management and OAuth handling
- `likelee-ui/src/auth/onboarding.ts` - Helper functions for auth intent and routing
- `likelee-ui/src/pages/ReserveProfile.tsx` - Creator signup flow
- `likelee-ui/src/pages/OrganizationSignup.tsx` - Brand/Agency signup flow
- `likelee-ui/src/auth/ProtectedRoute.tsx` - Route protection and onboarding redirect

### Current Issues:

1. **Login.tsx Line 173-189**: When no profile exists, redirects to signup but doesn't check if onboarding is incomplete
2. **Login.tsx Line 191-235**: When profile exists, only checks role match, then redirects to dashboard without checking `onboarding_step`
3. **AuthProvider.tsx Line 167-205**: `fetchProfile` creates a creator profile automatically if none exists, bypassing the signup flow
4. **Login.tsx Line 217-234**: Redirects to dashboard without checking if profile has `onboarding_step !== "complete"`

## Proposed Solution

### Phase 1: Fix Profile Completion Check

**File: `likelee-ui/src/pages/Login.tsx`**

Add logic to check if profile is complete before redirecting to dashboard:

```typescript
// After role match check, add onboarding completion check
if (initialized && authenticated && profile) {
  // ... existing role match code ...
  
  if (!roleMatchesTab) {
    setError("Account not found under this tab. Please try another tab.");
    setAccessDenied(true);
    logout();
    return;
  }

  // NEW: Check if onboarding is complete
  const isOnboardingComplete = !profile.onboarding_step || profile.onboarding_step === "complete";
  
  if (!isOnboardingComplete) {
    // Redirect to appropriate signup form to complete profile
    setIsRedirecting(true);
    const signupPath = getSignupPathForRole(
      profile.role as AuthIntentRole,
      authIntent?.creatorType || creatorType
    );
    navigate(signupPath, { replace: true });
    return;
  }

  // Only redirect to dashboard if profile is complete
  setIsRedirecting(true);
  // ... existing dashboard redirect code ...
}
```

### Phase 3: Improve Error Messages

**File: `likelee-ui/src/pages/Login.tsx`**

Update error message for role mismatch to be clearer:

```typescript
if (!roleMatchesTab) {
  const roleLabel = normalizedRole === "brand" ? "Brand" : 
                   normalizedRole === "agency" ? "Agency" : "Creator";
  setError(
    `Account not found under this tab. Your account is registered as ${roleLabel}. ` +
    `Please switch to the ${roleLabel} tab to continue.`
  );
  setAccessDenied(true);
  logout();
  return;
}
```

### Phase 4: Handle OAuth Return Properly

**File: `likelee-ui/src/pages/Login.tsx`**

Ensure OAuth return with no profile redirects to signup:

```typescript
// Line 173-189: Improve the no-profile case

  if (!profileResolved) return;

  // For authenticated users without profile, redirect to signup

    setIsRedirecting(true);

      signupRoleHint,
      authIntent?.creatorType || creatorType,

    navigate(signupPath, { replace: true });

```

### Phase 5: Update Signup Forms to Handle OAuth Users

**File: `likelee-ui/src/pages/ReserveProfile.tsx`**
**File: `likelee-ui/src/pages/OrganizationSignup.tsx`**

Both signup forms should:
1. Detect if user is already authenticated via OAuth
2. Skip email verification step
3. Pre-fill email from authenticated user
4. Show appropriate step (likely step 2 or 3)

```typescript
// Check if user arrived via OAuth
const { user, authenticated } = useAuth();
const isOAuthSignup = authenticated && user?.app_metadata?.provider === "google";

// Skip email verification if OAuth
const initialStep = isOAuthSignup ? 2 : 1; // or appropriate step

// Pre-fill email
useEffect(() => {
  if (isOAuthSignup && user?.email) {
    setEmail(user.email);
    setEmailVerified(true);
  }
}, [isOAuthSignup, user]);
```
